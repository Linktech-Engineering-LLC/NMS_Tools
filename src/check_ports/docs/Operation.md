## 1. Overview

`check_ports` operates as a deterministic, rule‑based port probe.
It performs:
* metadata construction
* port resolution
* per‑port connectivity checks
* enforcement rule evaluation
* Nagios exit code computation
* structured output generation

This document describes the operational phases executed during a typical run.

---

## 2. Operational Phases

`check_ports` executes the following phases in order:
1. Argument Parsing
2. Metadata Construction
3. Logger Initialization
4. Port Resolution
5. Port Checking
6. Enforcement Evaluation
7. Nagios Exit Code Computation
8. Output Generation

Each phase is deterministic and side‑effect‑free except logging and output.

---

## 3. Metadata Construction

Metadata is created by:
```python
meta = build_metadata(args, mode)
```

This phase:
* captures execution context
* records logging configuration
* stores operational mode
* initializes tool‑specific fields
* prepares dynamic fields for later population

Metadata fields include:
* `host`
* `timeout`
* `require_all`
* `require_any`
* `fail_only`
* `explicit_ports`
* `service_ports`
* `all_ports`
* `command`
* `mode`
* `logging_enabled`

Metadata is pure and contains no side effects.

---

## 4. Port Resolution

Port resolution is performed by:
```python
resolve_all_ports(args, meta, logger)
```

This phase:
* parses explicit ports
* resolves service names to ports
* merges and deduplicates all ports
* populates:
    * `explicit_ports`
    * `service_ports`
    * `all_ports`

Resolution errors (invalid ports, unknown services) produce `UNKNOWN` state.

---

## 5. Port Checking

Port checks are performed by:
```python
results, port_to_service = run_port_checks(args, meta, logger)
```

This phase:
* attempts TCP connections to each port
* applies timeout rules
* records `"open"` or `"closed"`
* builds a mapping of port → service (if applicable)
* populates the `results` list

Failures are recorded but do not immediately determine severity; enforcement rules decide final state.

---

## 6. Enforcement Model

Enforcement is constructed by:
```python
enf = build_enforcement_object(meta, results, port_to_service)
```

This phase:
* counts successes and failures
* applies rule filters:
    * `require_all`
    * `require_any`
    * `fail_only`
* determines enforcement state:
    * `"OK"`
    * `"WARNING"`
    * `"CRITICAL"`
    * `"UNKNOWN"`
* generates a human‑readable summary

The enforcement object is passed to the Nagios computation phase.

---

## 7. Output Model

Output is generated by:
```python
output_results(mode, args, meta, results, port_to_service, enf, code, logger)
```

Output varies by mode:

### Normal Mode
Human‑readable summary + per‑port results.

### Verbose Mode
Expanded detail including:
* metadata
* port resolution
* per‑port diagnostics
* enforcement object

### JSON Mode
Structured JSON containing:
* metadata
* results
* enforcement
* exit_code

### Quiet Mode
Exit code only.

### Nagios Mode
Nagios‑compatible single‑line output + exit code.

---

## 8. Nagios Behavior

Nagios exit codes are computed by:
```python
code = compute_nagios_code(enf, args)
```

Mapping

| State | Code | Meaning |
| --- | --- | --- |
| OK | 0 | All requirements satisfied |
| WARNING | 1 | Partial failure or soft rule violation |
| CRITICAL | 2 | Hard rule violation (require_all / require_any) |
| UNKNOWN | 3 | Invalid input or internal error |

Nagios mode suppresses logging but performs full enforcement.
